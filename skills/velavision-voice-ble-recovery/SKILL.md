# VelaVision 语音与 BLE 故障调查

目标是区分监听门、外设事务、音频取消尾部和服务退出，把一个明确故障推进到有来源、可复核的有限结论。该 Skill 于 2026-11-03 根据 R46→R49 已有材料整理，不能写成这些历史修复当时已经调用过它。

需要核对 R46→R49 的实现、证据或类似日志时，读 [R49 案例与证据索引](references/r49-case.md)。它是历史案例，不是当前板态。项目根目录指包含 `project-manifest.json` 的 VelaVision 目录；参考中的路径均相对该根目录。

## 先确定现场与授权范围

先读项目最新 README、manifest、代码日志对应表及相关专项收据，绑定实际运行镜像、持久化镜像、冻结源码与时间。RAM 候选和断电后的持久化版本可能不同；主 source50 WIP 不能替代冻结 R42/source49 加 overlay。`status.json` 可能保留早期 pending 字段，必须结合带时间和镜像身份的功能、读回、冷启动收据判断，保留历史失败。

只读调查先保留原始日志、状态和线程快照。用户称执行器失控或停机不确定时，先确认实际停机及现场供电状况，再继续复现；不可用日志中的 GATT 成功替代物理确认。加载此 Skill 不增加重启、执行器动作、RAM 加载、刷写或远程提交授权。已有授权足够时沿用，不重复索取确认。

## 收齐能区分故障的日志

优先保留故障前一轮成功到退出后的连续原始 UART，另存带 SHA256 和 `prefix_bytes` 的前缀，记录采集缺口、串口 owner 与端口。日志续写后全文件 SHA 改变不能直接判原快照损坏，应按记录字节数核对原前缀；没有字节数时只读找回匹配前缀并保留方法。断开电脑期间未采集的历史不能补造。需要这些字段时从已有日志检索，避免为了凑齐字段无目的重跑：

- `ASR_FINAL`、`PARAFORMER/PF_TIMING`、`NATIVE_LISTEN`、`NATIVE_INTENT`：是否仍在听、识别文本、有没有进入控制分支。
- `MICRO/MICRO_MANUAL`：活动/不确定状态、命令、事务与连接身份、0/1/2/3 写入返回、断连和退休；BLE reason 与无线 fault 只作观测，不直接等同根因。
- `TTS_SPOOL`、`REPLY_PIPELINE`、`NEAR_EXPERIMENT`、`APM21_FIRSTFAULT`、`ECHO_FREEZE`：owner、reply、TX generation、epoch、scope/lease、样本索引、cut/QUIET/SOURCE_END、取消与 PF 交接。
- `SESSION end`、`service_exit/sequence_exit` 与 native configured/running/stopping/last_error/report_error；若已退出，读取线程快照区分阻塞和收尾。
- 涉及报告时保留同一 epoch、task/report 身份、上传/摘要、本地提示、自动微晶序列和跟随回执；不把不同轮次拼成闭环。

## 从首个异常建立因果链

按同一 owner/reply/TX/epoch 的单调时钟建立“正常阶段 → 首个违约 → 下游超时/退出”表。交错 TRACK 文本可能切碎日志，保留原文并注明解析不完整；PC 分块到达时间不能冒充板端执行或声学时间。

将事实、确定性代码复现、与现场相符的推断分开。`-125` 常见于正常取消，不能单凭它判故障；后续 `-110` 可能是上游尾部阻塞造成的退役超时。R47 中 ASR/TTS 成功、near 取消、echo `-71`、约五秒后的退出 `-110` 是调查链，最后一条退出不是自动成立的首因。主动停止后 error 清零不能覆盖原首错；主动停采集产生的退出也不是原故障。

按证据选择分支，不把所有退出归为 BLE、ASR 或空闲休眠：

| 观测 | 优先核对 | 不足以证明 |
| --- | --- | --- |
| 最近唤醒超过普通 idle 阈值，控制无 ASR 窗口 | 平台监听门是否认识 manual active/uncertain | 用户时间估计不能单独证明首次漏停原因 |
| ASR 有文本而没有控制命中 | 当前整句语法、同音白名单、否定/引述及优先级 | 不因一次未命中扩大模糊启动词范围 |
| 命令命中后超时，下一轮持续被阻止 | ATT 事务与连接退休、旧回调和输出不确定状态 | 连接退役不等于电机已停 |
| 播放 near 取消后首错，再无新 ASR 窗口 | EOF/cancel 物理顺序、typed tail 的生产与消费边界 | 人工句尾插话成功不证明命中罕见晚 EOF 分支 |
| 报告成功但外设失败后语音退出 | 外设错误是否被提升为整个语音服务错误 | 不将真实音频故障或外部取消吞为可恢复成功 |

## 修复与复核必须保留的边界

- **监听门**：普通对话 idle 门不能让 manual active 或 stop-uncertain 失去停止入口；成功控制可刷新活动时间。保留音频所有权、取消、忙碌和无效时钟检查，不使睡眠对话被普通文本隐式唤醒。R46 的 40 秒门与 90 秒固定运行上限是该版本参数，调查新版本先读配置。
- **BLE 生命周期**：事务身份不复用，旧回调不能提交新请求；先使事务失效再取消。连接引用需等 DISCONNECTED 且 ATT 完全脱离后退休。协议超时与输出不确定分开保存；不靠清 busy/poisoned 绕过未知状态。新显式 STOP 只发 0 后断开；新显式 START 先 0 再原启动序列。故障不自动重试输出、续跑或重播；停机未确认时自动护理和新采图应拒绝。
- **音频 typed tail**：不改旧包 PCM、cancel0 或身份，不伪造成成功 EOF。生产端需要完整 EOF cut/clear、前缀与真实 QUIET 证明；消费端需要已绑定 OLD 身份、真实 onset 取消已提交、fired 和边界索引，以及连续完整 320 样本。保持 owner/input/mode/scope/lease/reply/TX/epoch、变换、退休和 PF claim 检查。typed 事件仅允许原尾部 staging；普通 reason0、未知 reason、错身份、重放、半帧仍拒绝。禁止以延长五秒超时、放行未知 RAW、改 PCM/cancel 位或吞 `-71` 代替修复。
- **外设失败隔离**：只有已成功报告之后的非取消外设依赖错误可进入专门恢复路径；检查精确 HOLD epoch/回执、有界预算、无 pending assessment、音频健康和控制身份，恢复到下一次监听。不要重新上传、重播报告或自动恢复跟随；真正音频失败、取消、陈旧 epoch、预算或 HOLD 不满足继续原失败收口。

## 选择有区分力的有限回归

先在冻结实际函数和依赖上复现旧缺陷，再验证修复；保留原基线、构建参数和失败尝试。适用时使用 O0/O2、生命周期及内存检查，但不能以模型桩替换实际被怀疑函数后声称原函数已通过。

选择与改动相符的正负控：跨 idle 门、连续多轮启停、写超时与旧回调注入、连接未完全退休、停机不确定时 PHOTO/自动护理拒绝；正常 EOF、硬取消、旧 cancel0 typed 正例与普通 reason0/错身份/部分帧负例；依赖失败后 worker 到下一次监听且不重播。测试夹具显式注入 observer 事件应标注为受控组件验证，不能声称实物自动复现罕见调度。

若任务已授权实机候选验证，使用项目已有停止守卫与独立镜像流程，不在本 Skill 重写驱动或加载工具。只请求当前不确定性所需的有限操作，例如三轮启停中一轮跨 idle 阈值但未达运行上限；中途/句尾插话后新唤醒问答；外设断连失败后语音存活及显式停止恢复；同身份真实报告的原固定 1档2秒→3档2秒→2档3秒→停止断开→恢复跟随。硬件操作不在当前授权内时交付该方案并继续只读分析。

发现新的首错、失去日志身份/采集连续性、执行器停机未知、回归前提不成立或超出约定预算，即保留现场并停止本项推进；不反复重启掩盖失败。CRC/预览、软件正控、有限真人反馈、持久化读回和冷启动分别计状态，不相互替代。既定回归通过后不为凑测试数重复硬件操作。

## 输出

交付一份能独立复核的调查收据：镜像/冻结源码身份；原始日志路径与哈希和缺口；首错时序及事实/推断；改动保持和拒绝的边界；正负控结果与夹具限制；实机用户反馈、板端状态及有限范围；当前 RAM/持久化版本和下一项有区分力的动作。引用项目相对路径，敏感原始资料留在规定目录。

不要宣称物理 ACK、外部声学延迟、100%识别/建连、长期稳定、真实罕见分支复现或完全脱离电脑运行，除非分别有对应证据。R49 的 GATT 返回与用户现场观察应并列记载；不能互相替代。
